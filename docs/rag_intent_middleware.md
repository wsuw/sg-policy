# 智能意图门控与前置知识注入中间件设计规范

## 一、 背景与性能优化动机

在先前的智能体交互链路中，系统采用传统的 **ReAct 智能体工具调用模式（Agentic RAG）**：
1. **第 1 轮 LLM 决策**：大模型接收包含长篇 Prompt 与工具定义，耗时 2~4 秒思考并生成 `ragflow_search` 工具调用参数；
2. **第 1 轮 HTTP 检索**：Python 后端发起网络请求查询 RAGFlow 知识库（耗时 4~5 秒）；
3. **第 2 轮 LLM 决策（偶尔循环）**：大模型判断切片不充分，继续发起第 2 次工具调用；
4. **最终综合生成**：大模型汇总上下文，撰写最终回答（耗时 20~40 秒）。

**导致问题**：单次问答总耗时高达 **45~70 秒**，首字延迟（TTFT）超过 15 秒，严重影响用户体验。而在 RAGFlow 原生 Chat 中，单次流式问答仅需 **3~5 秒**。

---

## 二、 架构设计：双层意图门控 + 前置知识注入 (Pre-Retrieval Middleware)

为了彻底解决延迟瓶颈，系统引入**前置知识注入中间件（RAG Intent Middleware）**，将架构升级为 **Pipeline RAG + 双层门控路由**。

```mermaid
flowchart TD
    A[用户输入提问] --> B{前置中间件: 双层意图门控}
    
    subgraph 门控判定层
        B -->|Layer 1: 0ms 正则与关键词拦截| C1{是否明确?}
        C1 -->|是| D1[得出意图结论 (0ms)]
        C1 -->|否 / 语义模糊| C2[Layer 2: 1-Token 微模型极速判别 (~300ms)]
        C2 --> D1
    end

    D1 -->|无需检索 (打招呼/闲聊/通用对话)| E[直接调用主大模型]
    D1 -->|需要检索 (政策/规划/电价/业务问答)| F[并发调用 RAGFlow Search API 提取切片]
    
    F --> G[组装标准知识库上下文 Context + [REF:n] 与 [DOC:xxx] 协议]
    G --> H[主大模型第 1 轮直接流式输出]
    E --> H
    
    H -->|首字延迟 < 1s, 总耗时 3~5s| I[CopilotKit 前端交互组件渲染]
```

## 三、 核心模块实现细节

### 1. 双层意图门控路由器 (Dual-Tier Gate)

#### 第一层：0 毫秒规则速判层（命中率 > 90%）
* **免检索拦截白名单（Casual Patterns）**：
  匹配常见的问候语、打招呼、系统操作与闲聊指令，例如：`你好`、`您好`、`hi`、`hello`、`你是谁`、`谢谢`、`再见`、`帮助`、`清空`、`写一首诗` 等。
* **直接检索特征词（Domain Keywords）**：
  匹配企业专有政策、规划与业务特征词，例如：`电价`、`电费`、`十五五`、`规划`、`预算`、`投资`、`需求`、`政策`、`标准`、`峰谷`、`时段`、`数智化`、`国网`、`计量`、`客服` 等。

#### 第二层：微型模型 1-Token 兜底判别（针对模糊提问，耗时 ~300ms）
* 当第一层规则未明确命中时（如：“*这个事情怎么办理？*”），激活极轻量模型进行 1-Token 极速判别：
  ```text
  Prompt: "判断以下提问是否涉及企业业务政策、规程、规划、指标或需要查阅企业文档。只需输出单一字符：'Y' 或 'N'。"
  Config: max_tokens=1, temperature=0
  ```

---

### 2. 前置切片上下文注入协议 (Context Injection)

当判定需要检索知识库时，中间件自动调用 RAGFlow API，并将清洗后的树形节点直接注入为 Prompt 上下文：

```text
<knowledge_context>
[REF:1]
├── Title: 上海市居民分时与阶梯电价政策.docx (相似度: 0.89)
└── Content:
上海市居民生活用电分时时段划分：峰时段为6:00-22:00（共16小时），谷时段为22:00-次日6:00（共8小时）...

[REF:2]
├── Title: 2027年数字化项目业务需求表(3).xlsx (相似度: 0.63)
└── Content:
...
</knowledge_context>

=== 真实引用来源文件列表 ===
[DOC:上海市居民分时与阶梯电价政策.docx]
[DOC:2027年数字化项目业务需求表(3).xlsx]
```

### 3. 引用与前端交互规范

大模型根据注入的上下文一次性流式输出：
1. **正文事实句**：在陈述句末尾规范标注 `[REF:1]`、`[REF:2]`，前端通过 `CitationBadge` 自动渲染为悬浮弹出卡片（**`Fig. 1`**，无命中切片时前端严密防呆，不渲染空标签）；
2. **文末来源汇总**：消息下方自动通过 `DocumentPill` 动态聚合渲染文件胶囊（支持 DOCX、XLSX、PDF），支持一键纯前端原生物档在线预览；
3. **辅助工具兼容**：
   - `comparePolicies`：当检测到同一业务的多版本历史更替或冲突时主动触发，驱动右侧打开比对工作台；
   - `calculate`：数学统计运算；
   - `generate_a2ui`：生成式数据看板与图表。

## 四、 性能提升实测指标

| 场景 | 改造前 (ReAct Agent 工具调用) | 改造后 (前置中间件 Pipeline) | 提升幅度 |
| :--- | :--- | :--- | :--- |
| **日常打招呼 / 闲聊** | ~4.5 秒 (思考+决策) | **< 0.5 秒 (0ms 拦截直出)** | **提速 90%** |
| **政策/电价知识库问答** | ~45 ~ 70 秒 (多轮循环) | **~3 ~ 5 秒 (首字 < 1s)** | **提速 85% ~ 90%** |
| **LLM Token 消耗** | 3 轮完整上下文传输 | **仅 1 轮单次传输** | **节约 60% 成本** |
